# 1. 시작하기

> 개발자: 박승우 · 일자: 2026-08-26
> 목표: **처음 받은 사람이 로그인 화면을 볼 때까지.** 배포는 [`DEPLOY.md`](../DEPLOY.md).

## 1. 무엇인가

식품 제조업체의 HACCP 기록을 쓰고 결재하는 웹 시스템이다.
업체마다 자기 자료만 본다(테넌트 = 회사코드).

| 층 | 무엇 | 포트 |
|---|---|---|
| `frontend/haccp-web` | React 18 + Vite 5 + TypeScript | 4173 |
| `backend/haccp-api` | Spring Boot 3.3.4 + MyBatis + Java 17 | 7070 |
| `db_sasshaccp` | PostgreSQL 스키마 `sasshaccp` | 5432 |

MES(`metis`)와 **완전히 별개**다. DB·포트·패키지가 모두 다르고 서로 참조하지 않는다.

| 도구 | 버전 | 확인 |

## 3. DB 부터

스키마 정본은 `db_sasshaccp/` **7본**이다. **빈 DB 에** 순서대로 깔면 끝난다.
이미 깔린 DB 에 다시 돌려도 된다 — 스키마가 있으면 `00_ddl` 과 `02_seed` 를 건너뛰고
`01_sp` 부터 돈다. 1회성 마이그레이션 본은 없다.

```sh
PGHOST=호스트 PGUSER=계정 PGPASSWORD=*** bash db_sasshaccp/apply-all.sh
```

끝나면 표·SP·메뉴·코드·사용양식 건수가 한 줄로 나온다.
앞 셋은 정본 파일에서 셀 수 있다 — 표는 `00_ddl.sql` 의 `CREATE TABLE`,
SP 는 `01_sp.sql` 의 `CREATE OR REPLACE`, 메뉴는 `02_seed.sql` 의 `tbl_menu`.
**화면이 늘면 SP·메뉴도 는다.** 어긋나면 문서가 아니라 정본을 세어 본다.
뒤 둘(코드·사용양식)은 시드가 upsert·distinct 로 넣어 실행 결과로만 확정된다.

새 업체를 여는 경우는 [`db_sasshaccp/README.md`](../db_sasshaccp/README.md) 의 「새 업체를 여는 법」.

## 4. 백엔드

```sh
cd backend/haccp-api
cp .env.example .env      # 값을 채운다. .env 는 git 금지
./mvnw spring-boot:run    # 또는 IntelliJ 에서 HaccpApiApplication Run
```

`.env` 에 없으면 기동이 안 되는 것: `JWT_SECRET` · `DB_HOST` · `DB_USERNAME` · `DB_PASSWORD`.

HWP PDF(문서함 인쇄 등)는 저장소 루트에서 한 번 깐다. IntelliJ 와 로컬 Docker 둘 다 이 스크립트다.

```sh
bash scripts/install_rhwp.sh
```

Windows 는 `tools/rhwp/rhwp.exe`(git 무시). Docker 는 볼륨 `haccp-rhwp` → `/opt/rhwp/rhwp`. `.env` 의 `APP_RHWP_CLI_PATH` 는 비워도 된다.

기동 확인:

```sh
curl -X POST http://localhost:7070/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"userId":"admin","password":"1234"}'
```

`{"success":true,...,"token":"eyJ..."}` 가 나오면 된 것이다.

## 5. 프론트

```sh
cd frontend/haccp-web
cp .env.example .env      # VITE_API_BASE_URL=http://localhost:7070

npm run dev
```

http://localhost:4173/haccp/ 로 들어간다. **basename 이 `/haccp/`** 다 — 루트로 들어가면 안 뜬다.

## 7. 첫 화면에서 무엇을 보나

로그인하면 좌측에 메뉴 트리가 뜬다. **화면은 29개**다.

| 대분류 | 중분류 | 화면 |
|---|---|---|
| 게시판 | | 오늘 할 일·대시보드 · 일정 캘린더 |
| 양식작성 | HTML 양식 | 일반위생·공정점검 작성 · CCP 검증점검표 작성 |
| | CCP 공정모니터링 | 포장 · 가열 · 금속검출 작성 |
| | HWP 양식 | HWP 작성 |
| 문서 현황·결재 | 결재 | 결재첨부 · 결재대기 · 결재완료 |
| | 문서함 | 문서함 |
| | 이탈·개선조치 | 이탈·개선조치 |
| 문서 | 작성 문서·주기 | 문서주기관리 |
| | HWP·양식 원본 | 사용양식관리 |
| | HTML·양식 원본 | 일반위생·검증·포장·가열·금속검출 양식관리 (5) |
| 시스템 | 권한·사용자·코드 | 공통코드·메뉴·권한그룹·부서·사용자·결재선 관리 (6) |
| | 이력·통계 | 로그인이력 · 화면통계 · 감사로그 |

화면마다 `<Route>` 가 **없다.** 식별자는 `scrnCd` 이고 URL 은 `tabRoute.ts` 의 `SCREEN_PATH` 가 정한다.

## 8. 업무가 어떻게 흐르나

```
문서주기관리   양식마다 언제 쓸지 정한다 (매일·매주·매월·분기·반기·매년·비정기)
      │
      ▼
오늘 할 일     오늘 써야 할 문서가 뜬다
      │
      ▼
작성 6화면     좌측에서 행추가 → 양식 선택 → 저장(문서번호 생김) → 우측 지면 입력 → 전송
      │                                                              status: WRK → REQ
      ▼
결재대기       결재자가 미리보기로 보고 승인 또는 반려
      │                                              승인 APV · 반려 RJT(작성자에게 돌아감)
      ▼
문서함         승인 끝난 기록. 조회만 된다
```

한계기준을 벗어나면 작성 화면에서 **이탈**을 켠다 → 개선조치 행이 생기고 이탈·개선조치 화면에 올라간다.

## 9. 바꾼 뒤 확인

```sh
# 프론트
cd frontend/haccp-web
npx tsc --noEmit ; npx eslint src e2e ; npx vitest run ; npm run build
npm run preview &             # 4173 에 dist/ 를 띄운다 — 빼면 전부 접속 실패
npx playwright test          # E2E — 화면·API·SP·DB 를 한 줄로 꿴다 (건수는 --list)

# 백엔드
cd backend/haccp-api ; ./mvnw -q -o test
```

**`mvn test` 통과가 기동 성공을 뜻하지 않는다.** MyBatis 매퍼 XML 은 컴파일에 안 잡힌다 —
패키지를 옮겼으면 반드시 기동해서 확인한다.

## 10. 막혔을 때

| 증상 | 볼 곳 |
|---|---|
| 기동이 안 된다 | `.env` 의 `JWT_SECRET`·`DB_PASSWORD` |
| 화면이 안 열린다 | `tabRoute.ts` · `ScreenAuthResolver` · `tbl_menu`·`tbl_role_screen` |
| 콤보가 비었다 | 공통코드를 코드만 올리고 데이터를 안 올린 것 (`03_code_seed.sql`) |
| 저장은 되는데 목록에 없다 | 회사코드가 다른 것. 서비스가 JWT 값으로 덮어쓰는지 확인 |
| 매퍼를 못 찾는다 | XML `namespace` 가 패키지와 다르다. 기동 로그를 본다 |
| HWP PDF 「변환기를 찾을 수 없습니다」 | `bash scripts/install_rhwp.sh` 후 API 재기동. IntelliJ 는 exe, Docker 는 `/opt/rhwp/rhwp` |
