# 4. 명명과 경로

> 개발자: 박승우 · 일자: 2026-08-26
> 규칙의 강제는 `.cursor/rules/01-project-core.mdc`. 여기는 **왜 그런지와 예외**를 적는다.

---

## 1. 한 줄 규칙

**URL = DB = 폴더 = 패키지.**

`/haccp` 와 `/api/v1` 바로 다음이 **대분류 / 중분류 / 화면코드** 순으로 같다.

```
URL   /draft/ccp-monitoring/ccp-htg
DB    tbl_menu   draft → ccp-monitoring → ccp-htg
FE    frontend/haccp-web/src/pages/draft/ccp-monitoring/
BE    com.haccp.draft.ccpmonitoring
XML   backend/haccp-api/src/main/resources/mapper/draft/ccpmonitoring/
```

한글 메뉴명은 URL 에 넣지 않는다.
Vite·Router basename 은 `/haccp/` 이고, 라우터 pathname 과 API 경로에는 `/haccp` 를 **다시 넣지 않는다.**

---

## 2. 왜 이렇게 하나

화면 하나가 일곱 층에 걸쳐 있다. 층마다 이름이 다르면 「이 화면의 서버 코드가 어디냐」를
매번 찾아야 하고, 옮길 때 한 층이 빠진다.

실제로 그런 사고가 있었다 — 패키지를 옮기면서 매퍼 XML 의 `resultType` 을 안 옮겨
기동이 안 됐다. **매퍼 XML 은 컴파일에 안 잡힌다.**

---

## 3. 자바 패키지의 예외 하나

자바 패키지는 하이픈을 못 쓴다. **중분류의 하이픈만 지운다.**

| URL 중분류 | 패키지 |
|---|---|
| `ccp-monitoring` | `ccpmonitoring` |
| `html-form` | `htmlform` |
| `hwp-doc` | `hwpdoc` |

그 밖의 차이는 규칙 위반이다. 2026-08-26 에 셋을 맞췄다.

| 전 | 후 | 왜 |
|---|---|---|
| `draft.hwp` | `draft.hwpdoc` | URL 이 `hwp-doc` 인데 패키지만 `hwp` 였다 |
| `docs.document` | `docs.documents` | URL 이 `/docs/documents` (복수) |
| `docs.template` | `docs.templates` | URL 이 `/docs/templates` (복수) |

**단수·복수도 맞춘다.** 예외를 두면 다음 사람이 어느 쪽인지 매번 확인해야 한다.

---

## 4. 절대 안 바꾸는 것

| 값 | 어디 | 바꾸면 |
|---|---|---|
| `scrnCd` | `tbl_screen`·`tbl_menu`·`SCREEN_PATH` | 권한·메뉴·통계가 끊긴다 |
| `persistId` | 그리드 열 설정 키 | 사용자가 저장한 열 너비가 날아간다 |

폴더·URL 이 바뀌어도 이 둘은 그대로 둔다.

---

## 5. 코드값 표기

| 대상 | 표기 | 예 |
|---|---|---|
| 경로에 실리는 값 (`scrn_cd`·`menu_cd`·`tmpl_cd`) | 소문자·하이픈 | `ccp-htg` · `html_ccp_htg_001` |

HTML 양식코드 접두는 `html_` 이다. `html_hyg_prc_*` · `html_ccp_{chk,pkg,htg,mtl}_*` · `html_sys_*`.
옛 `tml_ccp_*` 는 2026-09-03 에 `html_ccp_*` 로 옮겼다 — [`8_결정_이력.md`](8_결정_이력.md).
| 공통코드 `main_cd` | UPPER_SNAKE | `DOC_STATUS` · `HTML_INPUT_TY` |
| 공통코드 `sub_cd` | UPPER_SNAKE | `WRK` · `KEEP` · `RADIO` |

**`sub_cd` 는 업무 표에 저장되는 값과 같은 표기다.**
`tbl_template.doc_kind = 'HTML'` 이면 `sub_cd` 도 `HTML` 이다.

예외 하나: `tbl_schedule_rule.nonwork_rule` 은 저장이 소문자 `keep|prev|next` 다 —
저장 SP 가 `lower()` 로 접고 `sub_cd` 는 `KEEP|PREV|NEXT` 대문자다.
FE·Java 가 비교 전에 대문자로 올려서 붙는다. 어느 쪽도 혼자 고치지 않는다
(`.cursor/rules/07-haccp-db.mdc`).

코드만 바꾸고 데이터를 안 바꾸면 라벨이 안 붙어 **콤보가 빈 값**이 된다. 항상 같이 옮긴다.

## 6. DB 이름

| 대상 | 규칙 | 예 |
|---|---|---|
| 표 | `tbl_{업무}` · 하위는 `tbl_{업무}_{행}` | `tbl_document` · `tbl_document_approval` |
| 화면 SP | `sp_{scrnCd}_{동작}_000` | `sp_department_management_r_000` |
| 공용 SP | `sp_tbl_{표}_{동작}_000` | `sp_tbl_document_delete_blocker_r_000` |
| 보조 기능 | `sp_{화면}_{기능}_{동작}_000` | `sp_user_management_sign_u_000` |
| 동작 | `r` 조회 · `c` 등록 · `u` 수정 · `d` 삭제 | |

예외 하나: `sp_hwp_template_management_ensure_default_000` 은 끝이 `_r/_c/_u/_d_000` 이 아니다.
이름을 바꾸면 매퍼와 `docs/9` 가 같이 움직이는데 얻는 것이 이름뿐이다. 그대로 둔다.

점검(2026-08-26): 표 53 · SP 155 · **규칙 위반 0**. 인자 개수 불일치 0 · 컬럼 실재 0건.

## 8. 화면 코드를 정할 때

```
1. 이미 있는 화면인가          3_화면_지도.md 를 본다
2. 어느 대·중분류에 들어가나    tbl_menu 트리를 본다
3. 그 칸에서 유일한가          tbl_menu 는 UNIQUE (co_cd, menu_cd) 다 —
                              메뉴코드는 트리 전체에서 유일해야 한다
4. 한 번 정하면 안 바꾼다
```

중분류 아래 화면이 하나뿐이면 중분류 단을 생략해도 된다.
**미리 전 메뉴를 나누지 않는다** — 이번에 손대는 메뉴만 이 칸으로 옮긴다.

## 9. 하드코딩하지 않는 것

값을 조건문에 나열하면 그 값이 늘 때 조용히 빠진다. 실제로 그랬다.

```sql
-- 하지 않는다: 새 양식이 목록에서 사라진다
WHERE tmpl_cd ~ '^hwp_sys_0(0[1-9]|1[0-9]|2[0-7])$'

-- 한다: 값으로 판단한다
WHERE t.doc_kind = 'HWP'
```

`hwp_sys_028`~`038` 열한 종이 이 정규식 밖이라 화면에 안 보였다.

> 그 열한 종은 **2026-08-31 에 지웠다.** 볼륨에 실물 `.hwp` 가 없어 골라도 열리지 않는
> 껍데기였다(문서 0건). 지금 시스템 제공 HWP 는 `hwp_sys_001`~`027` 27종이고
> DB·시드·매니페스트·볼륨이 모두 27로 맞는다. 위 문단은 **정규식으로 나열하면 안 되는 까닭**의
> 기록으로 남긴다.

## 10. 저장형과 표시형 — 값의 모양

**같은 값이 DB 와 화면에서 모양이 다르다.** 이걸 안 맞추면 컴파일도 시험도 안 잡고
저장할 때 DB 가 `22001`(문자열 잘림)로 막는다. 2026-08-27 에 이 병이 **네 번** 났다.

| 무엇 | DB 저장형 | 화면 표시·입력형 | 바꾸는 자리 |
|---|---|---|---|
| 날짜 | `varchar(8)` **`20260827`** | `<input type="date">` = **`2026-08-27`** | `toInputDate` ↔ `fromInputDate` (`lib/docDateTime.ts`) |
| 시각 | `varchar(10)` **`09:10`** | `<input type="time">` = `09:10` | 그대로 |
| 일시 | `timestamp` | `YYYY-MM-DD HH:mm` | `fmtDateTime` (`utils/date.ts`) |
| 코드값 | `varchar(4)`~`varchar(20)` | 공통코드 표시명 | `useCommonCodes` |

### 규칙 넷

1. **날짜 컬럼은 `varchar(8)` `YYYYMMDD` 다.** `base_dt`·`occur_dt`·`action_dt`·`due_dt`·`retention_until` 전부.
   달력이 주는 10자를 그대로 보내면 저장이 막힌다.
   **그리드 `type: "date"` 셀은 `MesEditableGrid` 가 알아서 되돌린다** — 화면마다 변환하지 않는다.

2. **시각은 `HH:MM` 5자다.** 컬럼을 `varchar(4)` 로 잡으면 안 된다 —
   `tbl_ccp_metal_sens_row.check_time` 이 그래서 금속검출 일지를 한 장도 못 쓰게 만들었다.

3. **코드값을 화면에 하드코딩하지 않는다.** 공통코드가 정본이다.
   개선조치 화면이 `CANCEL`(6자)을 콤보에 박아 뒀는데 `status` 는 `varchar(4)` 였다 —
   **콤보에 있는데 저장이 안 되는 값**이었고, 같은 `OPEN` 을 오늘 할 일은 「미조치」로 불렀다.

4. **`dayjs` 는 구분자 없는 8자리를 못 읽는다.** `fmtDate` 가 먼저 `YYYY-MM-DD` 로 붙여 준다.
   안 그러면 화면에 `Invalid Date` 가 뜬다 — 양식 선택 팝업이 실제로 그랬다.

### 컬럼을 새로 만들 때

**화면이 보낼 값의 최대 길이를 세어 보고 폭을 정한다.** 위 셋은 전부
「그럴 리 없다」로 넘어간 자리였다. 세는 데 1분이면 된다.

```sh
# 어느 컬럼이 좁은지 훑어보기
node tools/q.mjs "SELECT table_name, column_name, character_maximum_length
                    FROM information_schema.columns
                   WHERE table_schema='sasshaccp' AND data_type='character varying'
                     AND character_maximum_length <= 10
                   ORDER BY character_maximum_length, table_name"
```
