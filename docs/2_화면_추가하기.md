# 2. 화면 추가하기

> 개발자: 박승우 · 일자: 2026-08-26
> 목표: 화면 하나를 **끝까지** 만들 때 손대는 것을 순서대로.

화면 하나는 **일곱 층**에 걸쳐 있다. 하나라도 빠지면 화면이 안 열리거나,
열려도 권한이 없다거나, 저장이 조용히 사라진다.

```
1. DB      tbl_screen · tbl_role_screen · tbl_menu
2. BE      com.haccp.{대}.{중} — Controller · Service · Mapper
3. BE      mapper/{대}/{중}/XxxMapper.xml
4. DB      db_sasshaccp/01_sp.sql 의 sp_*
5. BE      common/auth/ScreenAuthResolver
6. FE      shell/tabRoute.ts SCREEN_PATH · shell/screenRegistry.tsx
7. FE      pages/{대}/{중}/ — Page · Rule · README
```

---

## 0단계 — 이름을 먼저 정한다

이게 틀리면 나머지가 전부 어긋난다. 규칙은 [`4_명명과_경로.md`](4_명명과_경로.md).

| 정할 것 | 예 | 규칙 |
|---|---|---|
| `scrnCd` | `ccp-htg` | 소문자·하이픈. **한번 정하면 안 바꾼다** |
| URL | `/draft/ccp-monitoring/ccp-htg` | `/{대}/{중}/{scrnCd}` |
| 패키지 | `com.haccp.draft.ccpmonitoring` | 중분류의 하이픈만 지운다 |
| `persistId` | `ccp-htg-list` | 그리드 열 설정 키. **안 바꾼다** |

`scrnCd`·`persistId` 를 바꾸면 사용자가 저장한 열 너비가 날아간다.

## 1단계 — DB

### 1-1. 화면 등록

```sql
INSERT INTO tbl_screen (scrn_cd, scrn_nm, module_cd, sort_no, use_yn, ins_id, ins_dt)
VALUES ('ccp-htg', 'CCP 가열공정 작성', 'CCP', 4302, 'Y', 'system', now());
```

`tbl_screen` 은 회사코드가 없다 — 플랫폼 공용이다.

### 1-2. 메뉴 등록 (업체별)

```sql
INSERT INTO tbl_menu (co_cd, menu_cd, menu_nm, h_menu_cd, scrn_cd, sort_no, use_yn, ins_id, ins_dt)
VALUES ('0000', 'ccp-htg', 'CCP 가열공정 작성', 'ccp-monitoring', 'ccp-htg', 4302, 'Y', 'system', now());
```

`tbl_menu` 는 **업체마다** 있다. `UNIQUE (co_cd, menu_cd)` 라 메뉴코드는 트리 전체에서 유일해야 한다.

### 1-3. 권한 (그룹 × 화면)

```sql
INSERT INTO tbl_role_screen (co_cd, usrgrp_cd, scrn_cd, read_yn, write_yn, modify_yn, delete_yn, print_yn, ins_id, ins_dt)
SELECT '0000', g.usrgrp_cd, 'ccp-htg',
       'Y', CASE g.usrgrp_cd WHEN 'VIEWER' THEN 'N' ELSE 'Y' END,
       CASE g.usrgrp_cd WHEN 'VIEWER' THEN 'N' ELSE 'Y' END,
       CASE g.usrgrp_cd WHEN 'ADMIN' THEN 'Y' ELSE 'N' END, 'Y', 'system', now()
  FROM tbl_role g WHERE g.co_cd = '0000';
```

**여기가 비면 로그인해도 화면이 안 열린다.**

### 1-4. 씨앗에도 넣는다

위 세 INSERT 를 `db_sasshaccp/02_seed.sql` 에 같이 넣는다.
안 넣으면 빈 DB 에 깔 때 그 화면이 없다.

## 2단계 — SP

업무 SQL 은 **전부 SP** 다. 매퍼 XML 에 직접 SELECT 를 적지 않는다.

```sql
CREATE OR REPLACE FUNCTION sasshaccp.sp_ccp_htg_r_000(
    p_co_cd character varying,
    p_from_dt character varying,
    p_to_dt character varying
) RETURNS TABLE(...) LANGUAGE sql STABLE AS $$
    SELECT ... FROM tbl_document d WHERE d.co_cd = p_co_cd ...
$$;
```

- 이름: `sp_{화면코드}_{동작}_000` · 공용은 `sp_tbl_{표}_{동작}_000`
- 동작: `r` 조회 · `c` 등록 · `u` 수정 · `d` 삭제
- 업무 규칙 위반: `RAISE EXCEPTION '문구' USING ERRCODE = '45000'` → 400 + 그 문구
- **`CREATE OR REPLACE`** 로 쓴다. `CREATE` 로 쓰면 재적용이 막힌다
- `db_sasshaccp/01_sp.sql` 에 넣는다. 파일과 라이브 DB 목록이 같아야 한다

**양식코드·화면코드를 SP 안에 정규식으로 나열하지 않는다.**
그렇게 하면 새 양식이 늘 때 조용히 목록에서 빠진다.
구분이 필요하면 `tbl_template.doc_kind` 처럼 값으로 판단한다.

**컬럼을 새로 만들면 화면이 보낼 값의 길이를 세어 본다.**
날짜는 `varchar(8)` `YYYYMMDD`, 시각은 `varchar(10)` `HH:MM` 이다.
좁게 잡으면 컴파일도 시험도 안 잡고 저장할 때 `22001` 로 막힌다 —
[`4_명명과_경로.md`](4_명명과_경로.md) 10절에 실제로 난 네 건이 있다.

## 3단계 — 백엔드

폴더는 `com.haccp.{대}.{중}` 이고 매퍼 XML 은 `mapper/{대}/{중}/` 다. **둘이 같아야 한다.**

```
backend/haccp-api/src/main/java/com/haccp/draft/ccpmonitoring/
    CcpHtgDraftController.java     경로·요청 형식만
    CcpLogDraftService.java        업무 판단
    CcpLogDraftMapper.java         SP 호출 인터페이스
    README.md
backend/haccp-api/src/main/resources/mapper/draft/ccpmonitoring/
    CcpLogDraftMapper.xml          namespace = 위 인터페이스 FQCN
    README.md
```

### 3-1. Controller — 얇게

```java
@RestController
@RequestMapping("/api/v1/draft/ccp-monitoring/ccp-htg")
@RequiredArgsConstructor
public class CcpHtgDraftController {
    private final CcpLogDraftService service;

    @GetMapping("/list")
    public CommonResponse<List<DraftListRow>> list(@RequestParam(required = false) String tmplCd) {
        return CommonResponse.ok(service.list(tmplCd));
    }
}
```

형제 화면과 엔드포인트가 **글자까지 같다면** 공통 기반 클래스로 뺀다
(`CcpLogDraftControllerBase` 가 그 예다). 복제해 두면 한쪽만 고쳐져 어긋난다.

### 3-2. Service — 회사코드는 JWT 에서만

```java
public List<DraftListRow> list(String tmplCd) {
    // 본문에 coCd 가 실려 와도 쓰지 않는다 — 남의 회사 자료가 보인다
    return mapper.selectList(LoginUserContext.coCd(), tmplCd);
}
```

### 3-3. Mapper XML — SP 한 줄

```xml
<select id="selectList" resultType="com.haccp.draft.dto.DraftListRow">
    SELECT * FROM sp_ccp_htg_r_000(
        #{coCd,   mode=IN, jdbcType=VARCHAR},
        #{fromDt, mode=IN, jdbcType=VARCHAR},
        #{toDt,   mode=IN, jdbcType=VARCHAR}
    )
</select>
```

## 4단계 — 권한 해석

`common/auth/ScreenAuthResolver` 에 URL → `scrnCd` 를 등록한다.

**빠뜨리면 403 이 아니라 검사 없이 통과한다.** `resolve` 가 `Optional.empty()` 를 돌려주고
`ScreenAuthInterceptor` 는 empty 를 통과로 처리한다 — 로그도 안 남는다.
화면은 멀쩡히 도는데 VIEWER 가 API 를 직접 쳐서 저장·삭제할 수 있다는 뜻이다.

403 은 다른 데서 난다.

- 맵에는 넣고 `tbl_role_screen` 씨앗을 빠뜨렸을 때
- 새 URL 이 `/api/v1/docs/documents` · `/api/v1/docs/templates` · `/api/v1/sys/users/` 같은
  **넓은 접두**에 삼켜져 남의 화면 권한으로 판정될 때

## 7단계 — 시험

화면 하나를 만들었으면 E2E 도 하나 만든다. 최소한 이 둘이다.

```ts
// 되는 것
const at = await addRow(page, grid);
await fillCell(grid, at, "이름", "값");
expect(await saveAndConfirm(page, "/화면/save")).toBe(200);
expect(dbOne("SELECT ... FROM tbl_x WHERE ...")).toBe("값");   // DB 로 판정

// 안 되는 것
await btn(page, "저장").click();                                // 필수값 비운 채
await expect(page.getByText(/입력하세요/)).toBeVisible();
expect(dbOne("SELECT count(*) FROM tbl_x WHERE ...")).toBe("0"); // DB 무변화
```

**화면 문구가 아니라 DB 로 판정한다.**
「저장했습니다」를 띄우고 서버가 실패를 삼킨 사고가 실제로 있었다(E2E-001).

그리고 **스모크 배열을 손으로 늘린다.**

```ts
// e2e/screens.smoke.spec.ts 의 SCREENS 에 한 줄
{ path: "/board/calendar", name: "일정" },
```

이 배열은 `SCREEN_PATH` 를 읽지 않고 경로를 직접 들고 있다 — 자동으로 안 는다.
빠뜨리면 새 화면이 전수 스모크에서 **조용히 빠진다.**

## 마지막 점검

| # | 확인 |
|---|---|
| 1 | 빈 DB 에 `apply-all.sh` 를 깔면 이 화면이 나오나 (씨앗에 넣었나) |
| 2 | VIEWER 로 로그인하면 저장 버튼이 안 보이나. **API 를 직접 쳐도 막히나** |
| 3 | 본문에 `coCd:"9999"` 를 실어 보내도 내 회사로 저장되나 |
| 4 | 필수값을 비우고 API 를 직접 쳐도 막히나 |
| 5 | 삭제가 `validate-delete` → `delete` 2단계인가 |
| 6 | 폴더마다 README 가 있나 |
| 7 | **기동해서** 열어 봤나 (`mvn test` 통과로 갈음하지 않는다) |
| 8 | 생성 문서를 다시 뽑았나 — `bash scripts/audit_generated_docs.sh` |
| 9 | **쓰는 사람과 결재하는 사람이 다른 계정**으로 한 바퀴 돌려 봤나 |
| 10 | 스모크 배열(`e2e/screens.smoke.spec.ts` 의 `SCREENS`)에 새 화면을 넣었나 |
