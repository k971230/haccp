## 1. 도구가 넷이고 보는 것이 다르다

| 도구 | 무엇을 보나 | 못 보는 것 | 건수 |
|---|---|---|---:|
| `tsc --noEmit` | 타입 | 실행 시 동작 | — |
| `eslint` | 규칙·미사용 | 로직 | — |
| `vitest` | 순수 함수·규칙 모듈 | 화면·서버·DB | 130 |
| `mvnw test` | 순수 계산·권한 판정·서비스 분기 | **매퍼 XML·기동·DB** | 58 |
| `playwright` | 화면→API→SP→DB 한 줄 | 성능·부하 | 105 |

### 시험이 진짜 무는지 확인한다

통과만 보고 넘기지 않는다. **운영 코드를 일부러 깨뜨려 시험이 실패하는지** 본다.
안 깨지면 그 시험은 아무것도 보증하지 않는다 — 2026-08-26 에 실제로 그런 시험이 있었다.

```sh
# 예 — 사용양식 차단 검사를 지우고 돌린다. 실패해야 정상이다
```

| 깨뜨린 것 | 결과 |
|---|---|
| 사용양식 차단 검사 제거 | 1건 실패 |
| 감사 기록 제거 | 1건 실패 |
| `DeleteValidation.requireItems` 무력화 | **3개 시험 4건 동시 실패** |
| 결재취소(UNDO) 갈림길 제거 | 1건 실패 |
| 감사 코드(APV·RJT) 매핑 제거 | 2건 실패 |

**`mvn test` 통과가 기동 성공을 뜻하지 않는다.**
MyBatis 매퍼 XML 은 컴파일에 안 잡혀서, 패키지를 옮기면 컴파일·단위테스트가 다 통과하고
기동에서 터진다. 실제로 그랬다.

## 3. E2E 가 다른 점

**화면 문구가 아니라 DB 를 직접 읽어 판정한다.**

```
스펙 ──▶ 화면(4173) ──▶ API(7070) ──▶ SP ──▶ DB
     └────────── dbOne/dbRows ─────────┘
```

「저장했습니다」를 띄우고 서버가 실패를 삼킨 사고가 있었다 — 결재 전 경로가 500 인데
스모크도 단위 테스트도 전부 통과하고 있었다(E2E-001).

기준은 셋이다.

| 기준 | 뜻 |
|---|---|
| DB 로 판정한다 | 화면이 뭐라 하든 `tbl_*` 를 다시 읽는다 |
| 막히는지도 본다 | 중복키·필수값·권한 없음·상태 역행을 일부러 시도한다 |
| 이어 붙여 본다 | 업무 하나를 끝까지 (시나리오 A~E) |

**건너뛰는 시험은 없다.** 105건이 전부 실제로 돈다 —
`test.skip` 으로 조용히 넘어가면 기능이 죽어도 초록이 뜬다.

### 시험이 빠지기 쉬운 자리 (겪은 것)

| 함정 | 무슨 일이 났나 |
|---|---|
| **부정만 보는 시험** | 「시스템 양식은 안 지워진다」만 보면 삭제가 통째로 죽어도 통과한다. 실제로 그랬다 |
| **확인창 버튼 글자** | 삭제 확인창의 긍정 버튼은 「확인」이 아니라 **「삭제」** 다. 툴바와 글자가 같아 범위를 좁혀야 한다 |
| **화면마다 다른 삭제** | HWP 양식은 체크박스, HTML 양식 5본은 **활성 행**이다. 하드 삭제와 소프트 삭제도 갈린다 |
| **조회 완료를 안 기다림** | KPI 문구는 조회 전에도 떠 있다. 그것만 기다리면 0행을 보고 지나간다 |
| **순서 의존** | 앞 스펙이 만든 자료를 기다리면 순서가 바뀔 때 조용히 건너뛴다. 스스로 깔고 시작한다 |
| **전체에서만 깨짐** | 로그아웃이 스스로 `/login` 으로 보내는데 `login()` 이 `goto` 를 겹쳐 쳤다. 단독으로는 안 난다 |

## 5. 시험용 DB — 운영과 갈라 둔다

**E2E 는 자료를 지운다.** 5본이 `resetDocuments()` 로 `tbl_document` 를 전량 비운다.
운영 DB 를 상대로 돌리면 한 번에 운영 문서가 사라진다.

그래서 시험용 DB 를 따로 둔다.

```sh
# 한 번만 — 빈 DB 에 시드 6본 + 양식 표준 복사
node tools/seed_test_db.mjs            # 기본 sasshaccp_test
node tools/seed_test_db.mjs --db 다른이름
```

`backend/haccp-api/.env` 의 `DB_NAME` 을 그 DB 로 둔다.
로컬 백엔드와 `tools/q.mjs` 가 **같은 곳**을 보게 하려는 것이다.

### 안전장치 — 이름으로 막는다

시험용 DB 는 이름이 `_test` 로 끝난다. 자료를 지우는 헬퍼가 그걸 본다.

```
resetDocuments · purgeCompany · seedCompany
  → DB 이름이 _test 가 아니면 시험을 멈춘다

Error: 문서 전량 삭제 은(는) 시험용 DB 에서만 한다. 지금 DB 는 "sasshaccp" 이다.
```

정말 운영을 만져야 하면 `E2E_ALLOW_PROD_WRITES=1` 로 열 수 있다 — **손으로 켠다.**

### 시드만으로는 HTML 작성이 안 된다

시드 6본은 **표준 지면**(`tbl_check_item`)까지만 깐다. HTML 작성 5화면은
**회사 지면 버전**(`tbl_*_ver`)을 읽는데 그건 안 만든다 — 업체마다 지면이 다르기 때문이다.

`seed_test_db.mjs` 가 `tools/seed_test_forms.sql` 로 그 상태까지 만든다.
운영에서는 사람이 양식 원본 5화면에서 「행추가(표준 복사)」를 누른다
(`db_sasshaccp/README.md` 10절).

## 6. 로컬 도구가 있어야 하는 것

DB 대조와 문서 초기화는 `tools/` 를 쓴다. **도구와 접속정보가 둘 다 있어야** 돈다 —
`tools/q.mjs` 는 git 에 있지만 `backend/.env` 는 없다.
**없으면 그 시험은 skip 된다** — 빈 값을 돌려주면 검사가 조용히 통과해 더 나쁘다.

| 도구 없이 도는 것 | 도구가 있어야 도는 것 |
|---|---|
| 28화면 스모크 | 저장 결과 DB 대조 |
| 인증·권한·테넌트·상태전이 (API 직접) | 문서 흐름 |
| 문서함 조회 전용 확인 | 통합 시나리오 · 신규 업체 개설 |

CI(`Jenkinsfile.e2e`)는 지금 접속정보가 없어 DB 대조를 건너뛴다.
주면 그때부터 CI 도 DB 로 판정한다.

## 8. 스펙을 더할 때

- 판정은 **DB 로** 한다. 화면 문구는 보조다
- 정상 경로 하나에 **막히는 경우 하나**를 같이 넣는다
- 시험이 만든 자료는 `afterAll` 에서 되돌린다 — 사람이 쓰는 화면이다
- 셀렉터 요령이 생기면 스펙이 아니라 `helpers.ts` 에 넣는다
- **형제 화면이 있으면 전부 돈다.** 하나만 보다 놓친 적이 있다 —
  HTML 양식 5화면은 같은 프레임이지만 복사 SP 가 화면마다 다르다(E2E-007)

## 9. 이 셸 특유의 함정

`helpers.ts` 가 흡수한 것들이다. 스펙마다 다시 밟으면 원인을 찾기 어렵다.

| 함정 | 왜 |
|---|---|
| 숨은 탭의 버튼·행이 먼저 잡힌다 | 셸이 닫지 않은 탭을 DOM 에 남긴다 → `btn`·`grids`·`visibleRows` |
| 신규행 키가 두 가지다 | `__new_*` 또는 `pending` → `addRow` |
| 목록의 보이는 열이 폭에 따라 달라진다 | 문서 idx(`data-key`)로 행을 집는다 → `rowOfDoc` |
| 저장이 확인창을 거칠 때와 아닐 때가 있다 | → `saveAndConfirm` |
| 기록 표는 줄마다 라디오 그룹이 따로다 | → `fillPaperRequired` |
| 작성 목록에 문서번호 열이 없다 | 비우고 시작한다 → `resetDocuments` |
