## 2. 업로드 파일 관리 (전수)

### 2.1 물리 레이아웃

```
APP_FILE_ROOT/                    # env — 운영 Docker volume
├── _template/                    # app.template.directory 기본
│   ├── {한글파일명}.hwp          # 표준 양식 (DB에 바이너리 없음)
│   └── {coCd}/…                  # 회사 커스텀
└── {coCd}/
    └── {yyyy}/{MM}/
        └── {uuid}_{safeOriginal} # 문서첨부·서명·사진·PDF 산출
```

- DB에는 **상대 경로 문자열만** (`file_path`, `photo_path`, `form_path`)
- 예외: 사용자 서명은 파일이 아니라 `tbl_user.sign_img bytea`에 바이너리로 직접 담는다 (`71_migrate_sign_blob_ddl.sql`)
- API 응답은 필요 시 URL/다운로드 스트림 — 서버 절대경로 비노출 원칙 (`formUrl` 등)

### 2.2 저장 클래스

| 클래스 | 역할 | 설정 키 |
|--------|------|---------|
| `DocumentFileStorage` | 일반 첨부·서명·사진·CLI PDF 복사 | `app.file.root` · `app.file.max-bytes` |
| `TemplateFileStorage` | `_template` 읽기/쓰기/복사 | + `app.template.directory` |
| `TemplateFileNames` | 파일명 sanitize · relativeFormPath | — |
| `RhwpCliClient` | HWP→PDF | `app.rhwp.*` |
| `TemplateImportService` | 기동 시 manifest 복사 | `APP_TEMPLATE_IMPORT_*` |
| `TemplateManifestLoader` | `templates/manifest.tsv` | 하드코딩 목록 금지 |

**경로 규칙 (`DocumentFileStorage.save`)**

1. `validate` — empty / size > maxBytes 거부  
2. `safeName` — basename + 위험문자 → `_`  
3. 상대경로: `{coCd}/{yyyy}/{MM}/{UUID}_{safeName}`  
4. `resolve` — normalize 후 **root 밖이면 거부** (path traversal)

### 2.6 템플릿 import · form 404

- `APP_TEMPLATE_IMPORT_ROOT` 비우면 기동 import 스킵  
- `GET /templates/{tmplCd}/form` 은 **원본이 없으면 404**다 (2026-08-10, STEP 04 · G-05)
  - `form_path` 공백(= 유형만 등록) · `_template`에 실물 없음 → `NotFoundException` → 404
  - 잘못된 입력(코드 공백·미사용 양식·루트 이탈)은 그대로 400 — "대상 부재"와 "요청 오류"를 나눈다
  - 사용자 문구는 BE `TemplateFileStorage.FORM_NOT_UPLOADED` = FE `MES.formNotUploaded` 로 한 문장
  - 서버 로그에만 `coCd · tmplCd · formPath` 를 warn 으로 남긴다
  - FE 다운로드 버튼은 `formUrl` 없으면 disabled + 같은 문구 툴팁
  - `responseType=arraybuffer` 오류 본문은 `http.ts resolveErrorMessage` 가 디코딩한다 —
    이 분기가 없으면 axios 원문("Request failed with status code 404")이 사용자에게 보인다
- overwrite: `APP_TEMPLATE_IMPORT_OVERWRITE` (운영 기본 false)

### 2.8 서명 등록·사용 가이드 (G-24)

사용자·운영 정본. 판정: [`09` G-24](16_통합완성도_및_부족분.md). API 표는 §2.3.

#### 등록 경로 (둘 중 하나)

| 누가 | 화면 | 동작 | API |
|------|------|------|-----|
| 시스템 관리자 | `user-management` 「서명 업로드」 | 대상 사용자 행 선택 → 이미지 파일 | `POST /api/v1/sys/users/{userId}/sign` (`uploadUserSign`, httpFile) |
| 본인 | HWP 「서명 복사」 또는 냉장/CCP 행 서명 | 미등록이면 파일 선택 → 즉시 등록 | `POST /api/v1/sys/users/me/sign` (`uploadMySign`) |

- 허용 형식: png / jpeg / jpg / gif / webp (화면 `accept`)
- 저장: `tbl_user.sign_img bytea` + `sign_mime` · `sign_nm` — 물리 파일을 만들지 않는다
- 크기: §2.5 `APP_FILE_*` (기본 20MiB)

#### 사용 경로

| 화면 | 버튼/행위 | 성공 시 | 비고 |
|------|-----------|---------|------|
| HWP leaf (`HwpDocumentEditorPage`) | **서명 복사** | 클립보드에 이미지 → 편집기에서 **Ctrl+V(붙여넣기)** | `GET …/me/sign` blob → `ClipboardItem` |
| 냉장 CCP (`ColdMonitorPage`) | 행 서명 | 행 `signYn=Y` 표시 · 저장 시 SP가 `sign_img` 복사 | `GET …/me/sign-info`로 보유 확인(이미지 미수신) |
| 가열·멸균·여과 (`CcpGenericMonitorPage`) | 행 서명 | 냉장과 동일 | `fetchMySignInfo` · `uploadMySign` |

HWP는 rhwp에 직접 insertImage가 없어 **클립보드 경유**가 정본이다. DB형 CCP는 행에 보유 여부만 붙이고, 서명 실물은 저장 SP가 `tbl_user.sign_img`에서 그 행으로 스냅샷 복사한다.

#### 실패 시 (사용자 안내)

| 증상 | 원인 | 조치 |
|------|------|------|
| 「등록된 서명이 없습니다…」 | `sign_img` 없음 | 안내대로 이미지 선택(본인 등록) 또는 시스템관리에서 대리 등록 |
| 클립보드 복사 토스트가 warn | `navigator.clipboard.write` 거부(비HTTPS·권한·브라우저) | 이미지는 받은 상태 — 편집기에서 Ctrl+V 재시도. **운영은 HTTPS** (`https://…/haccp/`) |
| 서명 복사 후 붙여넣기 안 됨 | 포커스가 편집기 밖 · 브라우저 이미지 붙여넣기 제한 | 편집기 본문 클릭 후 Ctrl+V. Chrome/Edge 권장 |
| 업로드 실패(크기·형식) | maxBytes·비이미지 | png/jpg 등으로 재시도 · 한도 §2.5 |
| 타임아웃 | 대용량·느린망 | `VITE_API_TIMEOUT_FILE`(120s) · 파일 용량 축소 |
| 관리 화면 「사용자를 먼저 저장…」 | 신규 행 idx 없음 | 사용자 저장 후 서명 업로드 |

### 2.9 법적서류 PDF/HWP 정책 (G-25) — **동결(의도)**

**정책 한 줄:** 법적서류(`legal-document-upload`)는 브라우저 내 PDF/HWP **미리보기를 하지 않는다**. 좌·우 모두 **다운로드만** 제공한다.

| 구역 | 파일 | UI | API |
|------|------|----|-----|
| 좌 — 유형 템플릿 | 회사/표준 form 1건 (HWP 등) | `MesButton` download(indigo) · `formUrl` 없으면 **disabled** + `MES.formNotUploaded` | `loadHwpTemplateFile` ← `GET …/templates/{tmplCd}/form` (없으면 **404**, G-05) |
| 우 — 등록 문서 | 첨부 다건 · 대표는 **PDF 우선**, 없으면 `HWP_SRC` | 동일 download 버튼 | `downloadDocumentFile` ← `GET …/files/{fileIdx}/download` |
| 우 — 저장 시 업로드 | 선택 파일 | 행 저장 흐름 | `uploadDocumentFile` · kind=`PDF` \| `HWP_SRC` (확장자 `.pdf`면 PDF) |

**동결 이유**

1. 증빙 원본을 로컬 뷰어(한글·PDF 리더)로 확인하는 현장 업무에 맞춘다  
2. 인페이지 미리보기는 rhwp 임베드·PDF.js 등 별도 의존·보안·성능 범위가 커진다  
3. 미리보기 제거는 의도적 UX이며 회귀가 아니다 — **재도입은 별도 제품 STEP** (현행 백로그에 넣지 않음)

셸 상단 CRUD는 search만(패널 `GridCrudButtons`가 CRUD) — 기존 의도 유지([`09`](16_통합완성도_및_부족분.md)).  
코드 변경 없음 (STEP 27). 판정: [`09` G-25](16_통합완성도_및_부족분.md).

| 수평 이동 | coCd Context 강제 · body coCd 거절 |
| 화면 권한 | FE 5종 · 메뉴 SP 결합 |
| 관리자 | usrgrpCd ADMIN |
| 파일 접근 | download는 fileIdx+테넌트 SP 검증 후 Storage.read |

### 3.3 파일 보안

| 위협 | 완화 |
|------|------|
| Path traversal | `resolve` root prefix · Template `../`·절대경로·toRealPath |
| 파일명 조작 | safeName · TemplateFileNames.UNSAFE |
| 덮어쓰기 | UUID prefix |
| 용량 DoS | max-bytes · multipart limit |
| 타 테넌트 읽기 | 경로 coCd + DB 조인 검증 |

### 3.4 인젝션·XSS·오픈리다이렉트

| 위협 | 완화 |
|------|------|
| SQL | MyBatis `#{}` · SP 호출 (문자열 SQL 조립 없음) |
| XSS | `lib/sanitize` · 사용자 메시지 기술정보 strip |
| 오픈 리다이렉트 | `isSafeReturnPath` |
| 에러 누출 | 사용자=업무문구 / 로그=상세 |

### 3.5 시크릿·깃

- `.env` 커밋 금지 · JWT_SECRET 회전 시 전 세션 무효  
- Actuator: health/metrics만 — 상세 env 노출 금지  

### 3.6 의도적 미구현(보안 부채로 헷갈리지 말 것)

- Refresh token / 회전 — 없음 (단일 TTL)  
- CSRF 토큰 — Bearer+CORS credentials false 전제  
- 바이러스 스캔 — 없음 (운영 정책)  
- 객체 스토리지(S3) — 로컬/볼륨만
