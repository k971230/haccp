# e2e

Playwright E2E. **화면이 열리는가**가 아니라 **업무가 끝까지 도는가**를 본다.

수행 결과와 발견한 결함은 저장소 루트 [`E2E.md`](../../../E2E.md) · [`E2E_ERRORS.md`](../../../E2E_ERRORS.md).

## 파이프라인

```
스펙 ──▶ helpers ──▶ 화면(4173) ──▶ API(7070) ──▶ SP ──▶ DB
                └──────────── dbOne/dbRows ─────────────┘
                             (결과를 DB 로 직접 확인)
```

화면 응답만 믿지 않는다. 「저장했습니다」를 띄우고 서버가 실패를 삼킨 사고가 실제로 있었다
(E2E-001 — 결재 전 경로가 500 인데 스모크·단위 테스트는 전부 통과했다).
그래서 저장·삭제·상태전이는 **DB 를 다시 읽어** 판정한다.

## 파일

| 파일 | 맡는 것 |
|---|---|
| `helpers.ts` | 로그인·화면 열기·그리드 조작·DB 조회. 셀렉터 규칙을 여기 한곳에 둔다 |
| `screens.smoke.spec.ts` | 28화면이 열리고 콘솔·네트워크 오류가 없다 |
| `sys-common-code` `sys-master` `sys-user` `sys-approval-line` | 기준정보 6화면 CRUD·제약 |
| `sys-logs` | 로그인이력·화면통계·감사로그 (조회 전용 확인 포함) |
| `doc-cycle` `schedule-cycle-management` | 문서주기 7종·오늘 할 일 연동 |
| `docs-hwp-template` `docs-html-template` | 양식 원본 6화면. HWP 는 13.5MB 실파일을 올린다 |
| `draft-all` | 작성 6화면 + 이탈 → 개선조치 |
| `document-flow` | 작성 → 전송 → 승인 → 보관 한 바퀴 (회귀 고정) |
| `flow-approval` | 승인·반려·문서함 |
| `flow-attach` | 결재첨부에서 전송·재전송 차단·전송취소 |
| `flow-corrective` | 개선조치 조회·수정·삭제차단. 2026-08-26 에 옮긴 URL 이 정본인지도 본다 |
| `today-tasks` | KPI 5장·미완료 체크·기한경과·클릭/더블클릭 구분·`?add=1` 소비 |
| `shell-grid` | 셸이 전 화면에 주는 것 — 방향키(제어·비제어)·패널 활성 4케이스 |
| `screen-permission` | 권한 밖 화면 차단·계정 전환 시 이전 탭 정리 |
| `company-provisioning` | 신규 업체 개설·재실행 안전·회사 격리 |
| `security-constraints` | 인증·권한·테넌트·상태전이·입력 검증 |
| `scenario` | 통합 시나리오 A~E |

**152건 전부 실제로 돈다 — 건너뛰는 시험은 없다.**
`test.skip` 으로 조용히 넘어가면 기능이 죽어도 초록이 뜬다.
(로컬 도구 `tools/` 가 없는 CI 에서 DB 대조가 skip 되는 것은 별개다 — 아래 참조)

## 시험이 헛돌기 쉬운 자리

겪은 것만 적는다. 다음에 같은 자리에서 안 넘어지게 하려는 것이다.

| 함정 | 무슨 일이 났나 |
|---|---|
| **부정만 보는 시험** | 「시스템 양식은 안 지워진다」만 보면 삭제가 통째로 죽어도 통과한다. 2026-08-26 에 실제로 그랬다. **막는 것을 볼 때는 되는 것도 같이 본다** |
| **확인창 버튼 글자** | 삭제 확인창의 긍정 버튼은 「확인」이 아니라 **「삭제」** 다. 툴바 버튼과 글자가 같아 다이얼로그 안으로 좁혀야 한다 — `confirmDeleteBtn()` |
| **화면마다 다른 삭제** | HWP 양식은 체크박스, HTML 양식 5본은 **활성 행**이다. 하드 삭제와 소프트 삭제도 갈린다 |
| **조회 완료를 안 기다림** | KPI 문구는 조회 전에도 떠 있다. 그것만 기다리면 0행을 보고 지나간다 |
| **순서 의존** | 앞 스펙이 만든 자료를 기다리면 순서가 바뀔 때 조용히 건너뛴다. 스스로 깔고 시작한다 |
| **전체에서만 깨짐** | 로그아웃이 스스로 `/login` 으로 보내는데 `login()` 이 `goto` 를 겹쳐 쳤다. 단독으로는 안 난다 |

## helpers 가 흡수하는 함정

이 셸 특유의 것들이라 스펙마다 다시 밟으면 원인을 찾기 어렵다.

| 함수 | 왜 필요한가 |
|---|---|
| `btn` `grids` `visibleRows` | 셸이 닫지 않은 탭을 DOM 에 남긴다. 이름만으로 잡으면 **숨은 탭**의 버튼·행을 누른다 |
| `addRow` | 신규행 키가 `__new_*`(대부분) 또는 `pending`(HTML 양식 원본)이다. 건수로 세면 페이지당 10행에 걸린다 |
| `fillCell` | 셀을 한 번 눌러야 input 이 덮인다. td 순서를 숫자로 박으면 열이 늘 때 전부 깨져 **헤더 글자**로 찾는다 |
| `saveAndConfirm` | 저장은 대부분 확인창을 거치지만 전부는 아니다(HTML 양식 복사는 바로 나간다). 없는 버튼을 기다리다 멈추지 않게 한다 |
| `createDraft` | 작성 6화면은 좌측 저장까지 해야 `docIdx` 가 생기고 우측 지면이 열린다 |
| `fillPaperRequired` | 기록 표는 **줄마다** 라디오 그룹이 따로다. 한 그룹만 찍으면 다음 줄에서 막힌다 |
| `resetDocuments` | 작성 목록에 문서번호 열이 없어 「몇 번째 행이 내 문서인가」를 화면으로 못 가린다. 비우고 시작한다 |
| `dbOne` `dbRows` | 결과를 DB 로 확인한다 |

## 실행

```sh
npx playwright test                       # 전체
npx playwright test e2e/scenario.spec.ts  # 한 스펙
npx playwright test --last-failed         # 실패만
```

| 환경변수 | 기본 | 뜻 |
|---|---|---|
| `E2E_USER` / `E2E_PASS` | — | 관리자 계정 |
| `E2E_RO_USER` / `E2E_RO_PASS` | — | 조회 전용 계정. 없으면 권한 시험을 건너뛴다 |
| `E2E_API_BASE_URL` | `http://localhost:7070` | 백엔드 |

## CI 에서 DB 대조하기

`dbOne`·`dbRows`·`resetDocuments` 는 로컬 `tools/`(git 미포함)를 쓴다.
없으면 그 시험은 **skip** 된다 — 빈 값을 돌려주면 검사가 조용히 통과해 더 나쁘기 때문이다.

Jenkins(`Jenkinsfile.e2e`)는 지금 도구 없이 돌아 DB 대조 시험이 빠진다.
붙이려면 에이전트에서 아래를 준비한다.

1. `tools/` 를 CI 에 배치하거나(아티팩트·별도 저장소), 같은 일을 하는 psql 래퍼를 둔다
2. DB 접속 Credentials 를 `backend/haccp-api/.env` 형식으로 내려 준다
3. `hasDbTools()` 가 참이 되면 나머지는 그대로 돈다 — 스펙은 안 고쳐도 된다

도구 없이 도는 것: 28화면 스모크, 인증·권한·테넌트·상태전이(API 직접 호출),
문서함 조회 전용 확인. 도구가 있어야 도는 것: 저장 결과 DB 대조, 문서 흐름, 통합 시나리오.

## 스펙을 더할 때

- 판정은 **DB 로** 한다. 화면 문구는 보조다
- 정상 경로 하나에 **막히는 경우 하나**를 같이 넣는다
- 시험이 만든 자료는 `afterAll` 에서 되돌린다 — 사람이 쓰는 화면이다
- 셀렉터 요령이 생기면 스펙이 아니라 `helpers.ts` 에 넣는다
