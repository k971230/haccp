## 2. 업로드 파일 관리 (전수)

### 2.1 물리 레이아웃

```
APP_FILE_ROOT/                    # env — 운영 Docker volume
├── _template/                    # app.template.directory 기본
│   ├── {한글파일명}.hwp          # 표준 양식 (DB에 바이너리 없음)
│   └── {coCd}/…                  # 회사 커스텀
└── {coCd}/
    └── {yyyy}/{MM}/
        └── {uuid}_{safeOriginal} # 문서첨부·서명·사진·PDF 산출
```

- DB에는 **상대 경로 문자열만** (`file_path`, `sign_path`, `photo_path`, `form_path`)
- API 응답은 필요 시 URL/다운로드 스트림 — 서버 절대경로 비노출 원칙 (`formUrl` 등)

### 2.2 저장 클래스

| 클래스 | 역할 | 설정 키 |
|--------|------|---------|
| `DocumentFileStorage` | 일반 첨부·서명·사진·CLI PDF 복사 | `app.file.root` · `app.file.max-bytes` |
| `TemplateFileStorage` | `_template` 읽기/쓰기/복사 | + `app.template.directory` |
| `TemplateFileNames` | 파일명 sanitize · relativeFormPath | — |
| `RhwpCliClient` | HWP→PDF | `app.rhwp.*` |
| `TemplateImportService` | 기동 시 manifest 복사 | `APP_TEMPLATE_IMPORT_*` |
| `TemplateManifestLoader` | `templates/manifest.tsv` | 하드코딩 목록 금지 |

**경로 규칙 (`DocumentFileStorage.save`)**

1. `validate` — empty / size > maxBytes 거부  
2. `safeName` — basename + 위험문자 → `_`  
3. 상대경로: `{coCd}/{yyyy}/{MM}/{UUID}_{safeName}`  
4. `resolve` — normalize 후 **root 밖이면 거부** (path traversal)

### 2.3 API 엔드포인트 (파일)

| 용도 | Method · Path | FE |
|------|---------------|-----|
| 문서 첨부 | `POST /api/v1/doc/documents/{docIdx}/files` | `uploadDocumentFile` |
| 다운로드 | `GET /api/v1/doc/documents/files/{fileIdx}/download` | `downloadDocumentFile` |
| PDF | `POST .../export-pdf` | `exportDocumentPdf` |
| 양식 원본 | `GET/POST /api/v1/doc/templates/{tmplCd}/form` | load/save HwpTemplate |
| 자사 양식 | `POST /api/v1/bas/company-templates/create-custom` | `createCompanyTemplateCustom` |
| 내 서명 | `GET|POST /api/v1/sys/users/me/sign` (+ path) | systemApi |
| 사용자 서명 | `POST /api/v1/sys/users/{userId}/sign` | `uploadUserSign` |
| 건강진단 | `POST /api/v1/hyg/health-cert/{idx}/file` | `uploadHealthCertFile` |
| 설비 사진 | `POST /api/v1/bas/equipment/{idx}/photo` | `uploadEquipmentPhoto` |

FE 타임아웃: 전부 **`httpFile`** (`VITE_API_TIMEOUT_FILE=120000`).

### 2.4 DB 메타

| 테이블/컬럼 | DDL |
|-------------|-----|
| `tbl_document_file` | `03_ddl_doc.sql` — kind/nm/path |
| SP file CRUD | `15_sp_doc.sql` — `sp_tbl_document_file_*` |
| `tbl_user.sign_path` | `01_ddl_auth.sql` |
| `tbl_equipment.photo_path` | `04_ddl_master.sql` |
| 결재·버전 path | `03_ddl_doc.sql` |

문서 삭제 시 파일 행·물리 파일 정리 흐름은 `DocumentService.delete` + Storage.delete (코드 기준 Double Check 후).

### 2.5 크기 한도 (반드시 일치)

| 키 | 기본 |
|----|------|
| `APP_FILE_MAX_BYTES` | 20971520 (20MiB) |
| `APP_FILE_MAX_SIZE` | 20MB (multipart) |
| `APP_FILE_MAX_REQUEST_SIZE` | 25MB |

불일치 시 “요청은 통과·저장만 실패” 또는 반대 증상.

### 2.6 템플릿 import · form 404

- `APP_TEMPLATE_IMPORT_ROOT` 비우면 기동 import 스킵  
- `GET /templates/{tmplCd}/form` 은 **원본이 없으면 404**다 (2026-08-10, STEP 04 · G-05)
  - `form_path` 공백(= 유형만 등록) · `_template`에 실물 없음 → `NotFoundException` → 404
  - 잘못된 입력(코드 공백·미사용 양식·루트 이탈)은 그대로 400 — "대상 부재"와 "요청 오류"를 나눈다
  - 사용자 문구는 BE `TemplateFileStorage.FORM_NOT_UPLOADED` = FE `MES.formNotUploaded` 로 한 문장
  - 서버 로그에만 `coCd · tmplCd · formPath` 를 warn 으로 남긴다
  - FE 다운로드 버튼은 `formUrl` 없으면 disabled + 같은 문구 툴팁
  - `responseType=arraybuffer` 오류 본문은 `http.ts resolveErrorMessage` 가 디코딩한다 —
    이 분기가 없으면 axios 원문("Request failed with status code 404")이 사용자에게 보인다
- overwrite: `APP_TEMPLATE_IMPORT_OVERWRITE` (운영 기본 false)

### 2.7 화면별 파일 UX

| 화면 | 동작 |
|------|------|
| HwpDocumentEditor / 문서함 | 첨부 업로드·다운로드·PDF |
| HwpTemplateManagement | 표준 form GET/POST |
| LegalDocumentUpload | 유형 템플릿 1 + 문서 다건 · **download indigo** · 미리보기 없음 |
| HealthCert | 증빙 파일 |
| System users | 서명 이미지 |
| Master equipment | 사진 |

관리 UI “파일 서버 브라우저”는 **없음** — 문서/마스터 행에 묶인 메타로만 관리.

## 3. 보안 심화 (04 보완)

### 3.1 인증·전송

| 항목 | 구현 |
|------|------|
| 전송 보호 | 운영 HTTPS (배포) · 로컬 HTTP 개발 |
| API 인증 | Bearer JWT · login만 public |
| CORS | allowlist origin · credentials false |
| 비밀번호 | spring-security-crypto BCrypt (저장) |
| 잠금 | 연속 실패 → lockYn · 이력 F/L |

### 3.2 인가·테넌트

| 항목 | 구현 |
|------|------|
| 수평 이동 | coCd Context 강제 · body coCd 거절 |
| 화면 권한 | FE 5종 · 메뉴 SP 결합 |
| 관리자 | usrgrpCd ADMIN |
| 파일 접근 | download는 fileIdx+테넌트 SP 검증 후 Storage.read |

### 3.3 파일 보안

| 위협 | 완화 |
|------|------|
| Path traversal | `resolve` root prefix · Template `../`·절대경로·toRealPath |
| 파일명 조작 | safeName · TemplateFileNames.UNSAFE |
| 덮어쓰기 | UUID prefix |
| 용량 DoS | max-bytes · multipart limit |
| 타 테넌트 읽기 | 경로 coCd + DB 조인 검증 |

### 3.4 인젝션·XSS·오픈리다이렉트

| 위협 | 완화 |
|------|------|
| SQL | MyBatis `#{}` · SP 호출 (문자열 SQL 조립 없음) |
| XSS | `lib/sanitize` · 사용자 메시지 기술정보 strip |
| 오픈 리다이렉트 | `isSafeReturnPath` |
| 에러 누출 | 사용자=업무문구 / 로그=상세 |

### 3.5 시크릿·깃

- `.env` 커밋 금지 · JWT_SECRET 회전 시 전 세션 무효  
- Actuator: health/metrics만 — 상세 env 노출 금지  

### 3.6 의도적 미구현(보안 부채로 헷갈리지 말 것)

- Refresh token / 회전 — 없음 (단일 TTL)  
- CSRF 토큰 — Bearer+CORS credentials false 전제  
- 바이러스 스캔 — 없음 (운영 정책)  
- 객체 스토리지(S3) — 로컬/볼륨만  

부족 시 09 백로그로만 올림.
