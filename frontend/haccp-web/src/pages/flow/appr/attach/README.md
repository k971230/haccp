# 결재 첨부 (`attach`)

URL `/flow/appr/attach`. **내가 작성한 문서**의 원본·첨부·비고를 관리하고 결재 진행상태를 본다.
상위 [`../README.md`](../README.md) 에 결재 3화면 전체 흐름이 있다.

| 파일 | 역할 |
|---|---|
| `ApprovalAttachPage.tsx` | 렌더·상태·API. 좌 내 문서 목록 + 우 양식명·스테퍼·원본·첨부·비고(스크롤 하나). 좌우 `ResizableSplit`. 우측 `h2` 는 양식명. 작성 목록 `title` 은 식별용 |
| `ApprovalAttachRule.ts` | `SCRN_CD` · `PERSIST_ID` · `SPLIT_KEY` · 컬럼 · 첨부 상한 · 원본/첨부 분류 · 스테퍼 |
| `approvalAttachRule.test.ts` | 잠금·개수·분류·스테퍼 단위 테스트 |

## 이 화면에 없는 것

**문서 본문 미리보기가 없다.** 상신자는 작성 화면에서 이미 내용을 확인하고 보냈다.
본문 확인은 결재자 몫이라 `sign-ready`·`sign-ok` 에만 둔다.
첨부파일 자체의 미리보기(PDF·이미지)도 없다 — 파일명·다운로드까지다.

## 전송 · 전송취소

전송·전송취소 버튼은 결재대기·완료와 같은 `DocumentApprovalToolbar`(`writerActionsOnly`)다.
확인 문구·토스트도 툴바가 정본이다. 이 화면만 따로 구현하지 않는다.

| 버튼 | 상태 | 보내는 것 |
|---|---|---|
| 전송 | 전송대기 `WRK`·`RJT` | `REQUEST` — 결재 프로세스 시작 |
| 전송취소 | 전송 `REQ` | `CANCEL` — 전송대기로 복귀 |

전송 직전에 그 문서 상세를 읽어 작성 화면과 같은 `validateForTransfer` 로 필수값을 본다
(`onBeforeAction`). 이 화면에는 지면이 없어서 상세를 한 번 더 읽는 것이고, 규칙은 한 곳에만 있다.
승인 서명이 들어간 뒤의 전송취소는 서버가 막는다.

결재는 **전송 → 결재** 2단이다. 검토 단계는 없다. 진행 스테퍼는 `작성 · 전송 · 결재`.
끝난 칸은 파랑+「완료」, 지금 칸(전송 뒤의 결재)은 노랑, 반려면 결재 칸이 빨강+「반려」.
반려·결재취소 사유는 비고와 같은 읽기 전용 textarea 다. 사유는 줄마다 한 건, **최신이 맨 위**. 다시 전송해도 지우지 않는다.

## 원본 파일과 첨부 파일

같은 표 `tbl_document_file` 에 네 종류가 있다. 화면은 둘로 나눈다.

| 섹션 | 종류 | 할 수 있는 것 |
|---|---|---|
| 원본 파일 | 최신 `HWP_SRC` 1건 + `PDF` | **다운로드만.** 삭제 버튼 없음 |
| 첨부 파일 | `ATTACH` · `PHOTO` | 전송대기에서 추가·삭제. 문서당 5개 |

HTML 문서는 원본 파일이 없다 — 「HTML 지면 문서 — 작성화면에서 확인」. 완료본 PDF 가 생기면 원본 칸에 둔다.

「파일 추가」는 고른 파일을 바로 올린다. 파일선택·첨부 두 버튼이 아니다.

좌측 목록 「첨부」열과 우측 「n개 / 최대 5개」는 같은 기준이다 — 사용자 첨부만.

## 잠금 — 첨부와 비고의 기준이 다르다

| | 전송대기 `WRK`·`RJT` | 전송 `REQ` | 결재완료 `APV` |
|---|---|---|---|
| 첨부 추가·삭제 | 가능 | **불가** | 불가 |
| 비고 작성·수정 | 가능 | 가능 | 불가 |

첨부는 기록물이다. 상신 뒤에 바뀌면 결재자가 본 것과 최종본이 달라져 감사에서 문제가 된다.
고치려면 **전송취소** 후 수정한다.
비고는 메모라서 결재완료 직전까지 열어 둔다.

판정은 `canEditAttach` / `canEditRemark` 한 쌍뿐이고, 서버 SP 가 같은 기준으로 다시 막는다
(`sp_tbl_document_file_c_000` · `_d_000` · `sp_tbl_document_u_001`). 화면만 믿지 않는다.

## 「초기화」의 뜻

검색줄에서 조회 왼쪽, 빨간 틴트 「초기화」다. 저장하지 않은 **비고 입력**만 되돌린다.
DB 에 저장된 첨부를 일괄 삭제하는 기능이 아니다. 저장된 첨부는 행마다 있는 「삭제」로만 지운다.

## 권한

목록은 항상 로그인 사용자의 `writerId` 로 조회한다 — 화면 입력이 아니라 세션에서 온다.
서버도 `writer_id` 로 거르고, 비고 저장 SP 는 작성자 본인이 아니면 거부한다.

## 첨부 파일 저장 위치

DB(`tbl_document_file`)에는 경로만 넣고 파일 자체는 **서버 디스크**에 둔다 —
`{저장 루트}/HaccpLogBooks/{회사코드}/{양식코드}/{일자}/{일자}_{원본명}_{연번}.{확장자}`.
사진이 많이 붙는 양식이 있어 바이너리를 DB 에 넣지 않는다.
다운로드는 인증된 API 를 거치고, 물리 경로는 응답에 넣지 않는다.
